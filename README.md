# 研序 · 课题组研究成果管理系统

本仓库实现 **研究成果图谱前端、研究资料管理后台、PostgreSQL 数据层、实名注册登录与权限，以及四类图文说明在线编辑并转为 PDF**。登录默认进入成果展示前端；资料仅向已登录的课题组成员开放。

后台“文件共享空间”按科研项目展示原始论文、原始数据、说明文档和其他文件。项目管理者可拖拽或选择任意类型文件上传到“其他文件”，并为每份文件选择全域共享、指定用户或私有；表单上传的原始数据默认私有，其他材料默认全域共享。普通成员能浏览全部文件目录，只能下载自己管理的项目、指定共享或全域共享的文件；导师可下载全部文件并删除自己上传的文件；管理员可管理所有文件及共享权限。导师账号由管理员在“成员管理”中创建。

技术：Node.js / TypeScript、Express、PostgreSQL、React、Tiptap、Playwright Chromium。系统不包含虚构的研究成果或默认管理员密码。

模块划分、表的归属和跨模块事务见 [系统架构](docs/ARCHITECTURE.md)；按功能复审代码可从 [代码复审指南](docs/CODE_REVIEW.md) 开始。`npm run check:architecture` 检查依赖方向、公开入口、SQL 归属及读写边界，已接入 `npm run build`。日常提交前运行 `npm run format:check` 检查源码格式，使用 `npm run format` 自动整理。

## 本地运行（Windows 也适用）

需要 Node.js 22.12+。首次安装：

```powershell
npm ci
```

项目的 `.npmrc` 已配置国内 npm 镜像 `https://registry.npmmirror.com/`，对 Windows、Linux 均生效。临时切回官方源可用 `npm ci --registry=https://registry.npmjs.org/`；保留 `package-lock.json`，不需要改写锁文件中的下载地址。

**一键启动全部服务**：

```powershell
npm start
```

默认打开 **http://localhost:5173**；如果修改了 `APP_ORIGIN`，请打开该配置中的地址。该命令自动启动本地 PostgreSQL、执行数据库迁移，再启动后端 API、PDF 工作进程和前后台页面。按 **Ctrl+C** 统一停止本次启动的服务，已有数据和上传文件会保留。

停止时请等到出现“本次启动的服务已全部停止。”再关闭终端。数据库通过 PostgreSQL 自带的 `pg_ctl` 正常关闭；启动失败会给出具体原因，日志保存在 `.local/postgres.log`。如果日志提示旧进程占用共享内存，需要确认并清理本项目的残留 PostgreSQL 进程；不要删除 `.local/postgres` 数据目录。

首次没有 `.env` 时会自动生成随机数据库密码和配置，数据库保存在 `.local/postgres`、默认端口为 `55432`。已有自己的 PostgreSQL 时，复制 `.env.example` 为 `.env` 并设置连接信息；可连接的现有数据库会直接复用，退出时不会关闭它。如果旧的 `npm run dev` 仍在运行，请先关闭旧窗口中的服务，避免端口冲突。

**首次创建管理员**（保持 `npm start` 运行，另开一个终端，仅需执行一次）：

使用您自己的邮箱、真实姓名、单位，并自行设置密码：

```powershell
$env:ADMIN_PASSWORD = Read-Host '输入管理员密码（至少 10 位）' -MaskInput
npm run admin:create -- '你的邮箱' '你的真实姓名' '你的单位或课题组'
Remove-Item Env:ADMIN_PASSWORD
```

上述 `-MaskInput` 适用于 PowerShell 7。普通网页注册始终创建研究成员；不会把第一位访客自动设为管理员。重复邮箱不会被覆盖。管理员先在“要素与文件”添加可选要素类型；成员注册后即可创建研究成果。

复制命令时，环境变量名应为 `ADMIN_PASSWORD`，邮箱中不要出现反斜杠，例如 `name@example.org`。需要在设置密码的同一个 PowerShell 窗口运行 `npm run admin:create`。如提示数据库未连接，先在另一个终端保持 `npm start` 运行。

也保留分步命令：`npm run db:local` 启动数据库，`npm run db:migrate` 执行迁移，`npm run dev` 启动支持后端热重载的开发服务。原来只启动已构建后端的命令改为 `npm run start:api`，需另行运行数据库和 `npm run worker`。

`npm start` 提供前端热更新；修改后端代码后重新启动即可。要自定义本地服务监听端口，编辑 `.env`（没有该文件时首次运行 `npm start` 会自动生成）：

```dotenv
APP_ORIGIN=http://localhost:10086
PORT=10087
```

`APP_ORIGIN` 的端口是前端监听端口，也是浏览器访问地址；`PORT` 是后端 API 监听端口，两者必须不同且未被占用。默认分别为 `5173` 和 `3001`。`npm start` 与 `npm run dev` 都使用这两个设置，开发服务器会将 `/api` 请求转发到设置的后端端口。修改后重新启动服务即可生效。

本地工具会尝试使用 Windows 已安装的 Chrome。其他环境或没有 Chrome 时，执行 `npx playwright install chromium` 并留空 `.env` 中 `CHROMIUM_EXECUTABLE_PATH`。Linux 还需安装浏览器系统依赖和中文字体，如 `fonts-noto-cjk`。Windows 也可将该路径设为 Edge 的绝对路径。

## 使用顺序

### 研究成果展示前端

- 登录或刷新页面后默认进入 **研究成果图谱**。页面右上角的 **进入后台管理系统 / 回到前端** 切换两个界面；切换时保留当前后台编辑草稿，保存后的内容在返回前端时重新读取。
- 五列依次为 **产生机制 → 要素 → 经济影响 → 潜在风险 → 政策建议**。每类要素为深色核心节点，同一研究的四张摘要卡片按行对齐。产生机制连接要素，要素连接经济影响，右侧按同一研究串联“经济影响 → 潜在风险 → 政策建议”，使用深蓝色连线，转折处为圆角；风险和政策不再单独连回要素。悬停连线可查看从左向右流动的小圆点。
- 可按研究题目、要素类型、研究类型筛选。每类要素先显示最近更新的 3 项研究，点击“展开更多”继续读取；画布支持拖动、滚动、缩放和适应宽度。工具栏可以关闭连线动画，也会遵循系统的减少动态效果设置。
- 点击摘要卡片，在左侧阅读窗查看该研究的四类图文全文。桌面窗口占屏幕宽度的 30%，小屏幕使用更宽的阅读窗，手机全屏阅读；顶部章节按钮可直接定位相应内容。
- 阅读窗底部 **进一步了解这一研究工作？** 提供论文原稿 PDF 的新标签页预览和下载。没有上传论文时显示缺失提示；只有说明 PDF、尚未在线编辑的章节会提供摘要和说明 PDF 链接，不将摘要冒充全文。
- 继续使用 `research_records.documents` 中已保存并清理的 HTML、插图文件引用和修订信息；前端全文读取时再次清理 HTML。无需新增表或迁移已有数据。只上传 PDF 的历史材料无法自动恢复为可编辑图文，可在后台“图文说明”补充正文。
- 展示接口与文件访问均沿用登录校验。概览只读取摘要，全文及附件元数据在点击后按需加载；停用要素下的历史研究仍可查看。

### LLM 智能填充与摘要

升级后重新运行 `npm start`，启动时自动应用 `003_llm_settings.sql`。管理员进入左侧 **LLM 设置**，填写接口基础地址、模型名称和 API Key，勾选启用，保存并测试连接。支持 OpenAI Chat Completions 兼容接口，基础地址如 `https://api.openai.com/v1`，系统追加 `/chat/completions`；模型名称使用服务商提供的模型 ID。如服务不支持 `response_format`，关闭 JSON 模式再测试。默认不启用，不自带 API Key。

- **基本信息 → 智能填充与摘要**：以当前题目、经济数据名称、已填写摘要和已保存的四类图文说明为依据，也可补充粘贴研究长文。生成研究题目、研究类型、要素类型、经济数据名称及四类摘要建议；缺少原文依据的字段不填。要素类型只允许使用后台启用的选项。
- **图文说明 → AI 生成摘要**：直接读取当前编辑器正文，包括尚未保存的文字，只生成该篇说明对应的摘要。原稿与插图保留。
- 四类摘要使用省略主语的单段表达，直接陈述内容，不写“原文指出”“作者认为”“本研究表明”等转述开头，不使用标题和分点列表。保留因果识别和适用条件等限制；资料缺口显示在生成提示中，不混入摘要。
- 四类摘要统一按每项 200 字以内生成（标点等也计入），不再提供篇幅选项。后台逐项校验长度与字段类型，超长结果不会进入填充建议，也不直接截断；摘要分别对应产生机制、经济影响、可能风险和政策启示字段。生成后预览、勾选并“填入所选”，已有值默认不勾选。填入后仍是草稿，需要在基本信息页点击“保存研究资料”，沿用权限、版本冲突检查和操作记录。
- 本次长文至少 40 字、总原文最多 60,000 字；超限给出提示，不静默截断。单用户每 5 分钟最多 10 次模型请求，同时最多一个在途请求。可取消生成；超时默认 60 秒，可配置 10–180 秒。
- 仅向配置的模型服务发送研究文字；不自动解析上传的 PDF、图片、XLSX，不发送账户密码和上传文件。基本信息的整体生成使用已保存的说明，因此编辑图文后请先保存。数据字典中的短字段仍按原有方式填写。

API Key 在数据库中加密保存，浏览器只能查看“已保存”状态。加密密钥存于 `STORAGE_DIR/.secrets/llm.key`，迁移或备份时需与数据库、上传文件一起保留；丢失后须重新输入 API Key。更换服务地址时须重新填写密钥。测试连接发送固定测试消息，生成建议会调用配置的服务，并可能产生服务商费用。请核对生成内容后保存。

开发验证使用本地模拟 LLM，不需要外部密钥：`npm test` 和 `npm run test:integration` 覆盖接口格式、密钥加密、权限、超时、错误响应和生成不覆盖原文。真实服务的可用性以配置后的连接测试为准。

### 数据集预解析与在线数据说明

- 研究图片包支持 `.zip` 和 `.rar`，内容须为 PNG / JPG / WebP 图片；不支持加密、分卷或损坏的压缩包。
- 上传数据集时，系统解析所有非空工作表。每张表的第 1 行必须是连续、完整、不重复的文本表头，第 2 行起为数据；数据区不允许夹空行、合并单元格或孤立单元格。错误会提示工作表及行号或单元格位置，整批上传会被拒绝，原有材料仍然保留。
- 尾部只有格式的空白行列会被忽略。普通缺失值可保留并提示；上下左右均无其他数据的孤立单元格需要检查。最多 20 张工作表、每表 20 万行、全文件 500 个字段和 100 万个非空单元格。
- 字段只有数值时识别为“数值型”；文本、混合类型、日期和空列识别为“文本型”，保留 `001` 等文本编码。公式使用工作簿中已保存的结果，缺少结果或含 Excel 错误值时需先在 Excel 中修正、计算并保存。
- 上传成功后，点击“数据指标说明表”旁的 **＋ 在线填写**。数据 ID（原表头）与数据类型自动填充、不可手动修改；填写中文名称、解释和来源，确认面板数据标识后保存。多工作表的字段按“工作表 + 列”区分。
- `id/city/province/城市/省份` 等名称预选为“个体标识”，`time/year/date/年份` 等预选为“时间标识”，其余为“一般数据”。同一 XLSX 数据集内两种特殊标识各最多一个，也允许一个都不选；多个候选会在弹窗顶部提示，调整后方可保存。
- 中文名称最多 10 个字符、来源最多 20 个字符、解释最多 100 个字符，均必填且允许英文缩写。前后端都会校验。
- 说明绑定到具体的数据集文件版本；重新上传后新版本单独解析、填写，旧说明可在弹窗的版本选择框中查看或继续编辑。成员只能编辑自己的研究成果，管理员可编辑全部，其他已登录成员只读查看。
- 升级前的历史数据集会在上传者首次打开在线填写时补做解析。原有 XLSX 指标说明表仍可照常上传，在线说明独立保存。

新增表 `dataset_descriptions`：`dataset_file_id` 外键关联 `file_mappings.id`，`profile` 保存自动解析的字段和类型、工作表行数及检查提示；`descriptions` 按字段 key 保存面板标识、中文名称、解释和来源，并记录修订版本、保存人和保存时间。运行 `npm start` 自动应用迁移 `002_dataset_descriptions.sql`。

供后续调用的接口（均要求登录，写操作要求成果编辑权限和 CSRF 校验）：

| 接口 | 用途 |
| --- | --- |
| `GET /api/datasets/:fileId` | 读取该数据集版本的解析字段及在线说明 |
| `POST /api/datasets/:fileId/parse` | 为历史文件补做解析；已解析时直接返回 |
| `PUT /api/datasets/:fileId` | 保存说明，提交 `revision` 和完整 `fields` 数组；并发版本冲突返回 409 |

### 成果归档

1. 管理员创建要素类型，例如劳动力、资本或课题组自己的分类。
2. 成员实名注册，用邮箱和密码登录。姓名与单位必填，暂不验证邮箱，也不进行身份认证。
3. 点击右上角“进入后台管理系统”，新建研究成果，填写题目、三选一研究类型、单选要素类型、四类摘要和经济数据名称。
4. 在“研究材料”批量上传图片 ZIP、数据 XLSX、指标说明 XLSX、论文 PDF；也能直接上传四份说明 PDF。
5. 在“图文说明”分别编辑产生机制、经济影响、可能风险和政策启示。支持图片粘贴、拖入、上传和表格。保存后可继续修改，点击“保存并生成 PDF”完成归档。
6. 查看“上传记录”追溯操作人和历次文件；在“要素与文件”按要素查看当前文件或所有历史版本。

普通成员可以查看全部组内资料、修改自己创建的成果；管理员可以修改全部成果并管理账号。停用成员或更改权限会撤销其已有登录。

## Docker 部署

包含 PostgreSQL、迁移、API/静态网页、独立 PDF worker 四个服务。需要已启动的 Docker Engine。

```powershell
Copy-Item .env.docker.example .env.docker
# 编辑 .env.docker，设置一个足够长的随机十六进制 POSTGRES_PASSWORD
docker compose --env-file .env.docker up --build -d
```

本机试运行默认打开 `http://localhost:3001`。Docker 中前端静态页面与 API 由同一服务提供；如需更改其监听端口，在 `.env.docker` 中同时修改 `PORT` 和 `APP_ORIGIN` 的端口，例如 `PORT=10087`、`APP_ORIGIN=http://localhost:10087`。要部署到服务器，请先配置 HTTPS 反向代理，然后设置 `APP_ORIGIN=https://你的域名`、`NODE_ENV=production`、`COOKIE_SECURE=true`；有一层受信任反向代理时设 `TRUST_PROXY=1`，并只允许代理访问应用监听端口。正式模式在未配置 HTTPS 安全 Cookie 时拒绝启动。数据库端口不向宿主机公开。

容器内创建管理员：

```powershell
$env:ADMIN_PASSWORD = Read-Host '输入管理员密码（至少 10 位）' -MaskInput
docker compose --env-file .env.docker exec -e ADMIN_PASSWORD app node dist-server/server/auth/create-admin.js '你的邮箱' '你的真实姓名' '你的单位'
Remove-Item Env:ADMIN_PASSWORD
```

文件卷和数据库卷必须持久化并配套备份。不要执行 `docker compose down -v`，它会删除这些卷。浏览器转 PDF 由 worker 执行，关闭 worker 后资料保存仍可用，PDF 任务会等待。

## 验证与维护

```powershell
npm run build
npm test
npm run test:integration
```

集成测试单独启动 `127.0.0.1:55433` 的临时 PostgreSQL，使用测试账号和隔离的文件目录，不写入业务库。它会检查权限边界、CSRF、格式校验、上传快照、并发编辑、要素映射级联、会话撤销与四类中文图文 PDF。测试 PDF 输出在 `output/verification`。需要可用 Chrome 或 Playwright Chromium。

源码结构：

```text
client/                 登录、中文管理界面与图文编辑器
client/showcase/        分层研究图谱、连线动画与图文阅读窗
server/showcase/        展示概览、分组分页与全文读取接口
server/auth/            注册、登录、会话、角色管理
server/research/        研究资料、审计快照、并发控制
server/files/           文件校验、私有保存、授权读取
server/documents/       HTML 清理、PDF 任务和独立 worker
server/factors/         管理员定义的要素目录
server/db/migrations/   可重复执行的 PostgreSQL 迁移
shared/contracts.ts    前后端共享类型与输入规则
tests/                 单元与真实数据库集成测试
```

详细说明：[数据库字段与关系](docs/DATABASE.md)、[API 接口](docs/API.md)。编辑器和 PDF 输出参考 [Tiptap 官方文档](https://tiptap.dev/docs/editor/getting-started/install/react) 与 [Playwright 官方 PDF 接口](https://playwright.dev/docs/api/class-page#page-pdf)。

第一版边界：不提供公开发布、多人实时共同编辑、邮件认证/邮件找回密码、任意 PDF 反向编辑、超大文件分片上传。默认单文件 25 MB、单次 100 MB；认证限流为单进程内存策略，若多实例部署，应改用共享限流存储。私有文件服务需要登录；正式部署应限制到课题组网络或配置邀请码 `REGISTRATION_INVITE_CODE`。
